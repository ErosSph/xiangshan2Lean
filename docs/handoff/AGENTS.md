# Chisel2Lean 项目工作规则

本文用于本项目工作区。已有 AGENTS.md 时先审查并合并，不覆盖原有规则。完整目标与证据见 `CHISEL2LEAN_HANDOFF.md`；后续用户明确修改的要求优先。

## 项目范围

只做 **Chisel → 参数化语义 IR → Lean 4 自动翻译器**。保留支持范围内的参数、位宽、组合逻辑、状态、复位、更新优先级和参数化结构。

用户已确认基于 Chicala fork：审查并复用源级 Typed AST 前端与相应 Pass，增加明确的参数化 IR 和 Lean 后端。标准 Chisel/CIRCT/兼容 RTL 路线仅作独立行为参考。

不做 AI Agent、自然语言规格生成、自动定理证明、证明知识库、论文结果复现、参数化 RTL 后端或 FPGA 部署。Sparkle/CIRCT 不是当前待大改的主线工程。

## 当前任务

先完整读取 `CHISEL2LEAN_HANDOFF.md`。当前执行任务仅为 **T0-CHICALA-FRONTEND-AUDIT**：环境与版本确认、上游基线构建/翻译、源码与 Pass 审查、少量参数/状态探针、证据报告和 Lean 后端接入建议。

若已有 `TASKS.md`，先确认它是否属于本项目及是否反映后续用户批准的进度。T0 完成后汇报结果和 M1 文件级计划，不默认继续大规模实现。

## 不可违反的实现原则

- Counter 是测试用例，不是最终支持范围；不得按模块名套用手写 Lean 模板。
- 不通过固定 n、超大哨兵数、文本替换或实例回推来冒充参数保留。
- 不机械地把 Scala Int 当成无界 Nat；不忽略符号宽度、截断和参数合法性。
- 明确区分 Scala 生成时条件/循环与硬件 when/周期状态迁移。
- 不把 RegInit 无条件解释成上电状态；不得给未知/未复位状态随意补零。
- 寄存器更新须保留旧状态读取、同步更新及连接优先级。
- 输出可能依赖当前输入，不得强制只从状态计算。
- 遇到不支持构造要准确报错并定位源码；不得静默跳过、修复源电路或填入不透明语义。
- 不用 sorry/admit/新增公理掩盖后端缺失；Lean 运行时语义辅助定义可以存在，但不扩展为证明框架。
- Lean 能编译、参数仍存在、仿真一致是不同证据；不能相互替代。

## 工作区和依赖

- 工作区与用户 fork 尚未在交接中指定。只在用户明确打开的项目范围内工作；冲突时确认。
- 不复用其他项目的路径、主机、Git 仓库或环境假设。
- 修改前检查分支、HEAD、git status 和已有文件；保护用户未提交修改。
- 上游参考提交为 `c8bab84b24c448c611b8bf2a87c7e9c26014b081`；这是远程观察，不是已安装基线。
- 上游声明 Scala 2.13.10、sbt 1.8.2、Chisel 3.5.6、chiseltest 0.5.6。实际使用前复核；不擅自升级。
- Lean 版本尚未冻结；选择后固定到 lean-toolchain。没有工具时如实记录，不虚构运行。
- 不执行破坏性的 reset/clean、删除用户资料、自动 push/发布、无授权系统安装或大规模依赖编译。
- T0 允许隔离的审查用例和最小调试输出，不借机重写整个 Chicala 前端。

## 测试和证据

每次实验保存命令、cwd、工具版本、退出码、stdout/stderr、变更和产物。特别注意上游 make test 主要是示例编译/翻译，不等于已经运行语义测试。

构建阻塞可继续静态审查，但状态必须是 PARTIAL/BLOCKED；不能以手写 Lean 模型替代失败的真实翻译。

差分参考必须来自原始 Chisel 与独立标准工具链，且采样、复位、初态、参数一致。不得把有限配置测试称为所有参数的形式化语义保持证明。
