## 2. 实现方法

```text
香山原工程 + 固定配置
    ↓ 官方 Chisel 7.3 展开
CHIRRTL
    ↓ 官方 CIRCT / firtool
SystemVerilog
    ↓ 原生 64 位 Yosys + slang 前端
层次导入 → 扁平化 → clk2fflogic / 存储器降低
    ↓ 官方 write_functional_smt2
FunctionalIR
    ↓ 本项目的导入器和 Lean 后端
Lean 模型：输入、当前状态 → 输出、下一状态
```

Scala、CDE、父类、trait、`Seq/Option` 都由真实香山工程执行，不再靠我们手写解析这些源码结构。CIRCT 负责官方硬件降低，Yosys 负责整理连接、位宽、时钟及状态关系；我们主要实现 FunctionalIR 到 Lean 的桥接、执行器和对照测试。

早期 Chicala 源码转换、参数化 IR 和 FIRRTL 路线仍保留，用作已有功能及交叉检查；完整香山当前走上面的 RTL 路线。接手时不必重新实现 Scala 前端，也不必重新引入 `save_n` 一类约定。

### 为什么新增 table 后端

原先的 source 后端直接生成 Lean `BitVec` 运算定义。已加入分块和记录分组，但整颗源码仍达到约 549 MB，实际 Lean 编译遇到内核递归问题。当前问题不仅是 Python 内存，也包括 Lean 表示和编译规模。

table 后端把相同 FunctionalIR 编成 `.circuit.bin/.circuit.hex`，用短 Lean 入口调用通用解释器 `lean/Chisel2Lean/Functional.lean`。解释器实现 29 类操作，以 Lean `BitVec` 计算输出和下一状态。解码检查位宽、类型、节点引用及初态约束的结构；执行时由 `initialValid` / `runRequest` 检查调用者提供的初态是否满足已知位。

生成模型通过 `#eval` 解码并校验全部数据，驱动核对 `C2L_TABLE_CHECK` 中的节点和字段数量。`CheckedCircuit` 携带数据校验成功的证明；**这证明数据通过当前校验器，不等于转换器语义正确性证明。**

`--lean-backend auto` 在节点数超过 100,000，或输入、状态、输出任一字段数超过 8,192 时选择 table；也可显式指定 `source` / `table`。

大文件读取已流式化，Python 节点采用紧凑数组保存。但全部节点列和名字绑定仍驻留内存，Lean 也需装入整张电路表和每步中间值。table 存储器采用稠密 `Array`，长度为 `2^addressWidth`。目前不能声称已经解决整颗容量和执行性能。

## 4. 语义和边界，接手时必须保持

- **二态模型。** X/Z 数据及未驱动信号转为显式任意输入，调用者提供具体值；不模拟 IEEE 四态传播。很多现有实验选择未知位为 0，这是测试选择，不是硬件上电保证。
- **初态显式提供。** 已知位必须满足 Yosys JSON 恢复出的约束。官方 SMT 序列化把未知初态写成零，本项目不直接采用这些零断言，不能为了方便改成隐式全零初始化。
- **时钟采用显式采样。** 整颗入口使用 `global`，每行输入是一次全局采样，调用者驱动所有时钟和复位；数据及门控信号须在有效边沿前稳定，复位释放与有效边沿分开。它不描述任意延时和竞争。默认 `single` 执行器则自动低、高两步。
- **执行还要检查定义域和事件。** 有效路径除零会被拒绝；直接调用 runtime 时不能只取 `outputs` 而忽略 `outputDefined`、`transitionDefined`、`checksValid`。assert/assume 失败拒绝执行，cover/print 保留为观察事件。
- **初始化配置要区分。** 整颗当前使用官方 `--disable-all-randomization` 的 `caller-state` 配置。初始事件之前，它与默认 RTL 可能不同。已有 260 步初始化回归对照默认原始 RTL，覆盖初始复位高/低和非零复位值，但这不是整颗初始化等价证明。[报告](validation-circt-initialization-7.3.json)
- **外部环境仍有范围。** 没有通用 DPI、任意外部 SRAM 宏或系统任务模型。已支持的存储器、冲突规则和日志桥接不能推广成所有厂商宏、MBIST 或启用后的 Difftest 环境。未支持情况应明确报错。

### 有没有改香山

香山硬件 Scala 源码未修改；本地增加构建、配置和端口适配。[源码审计](validation-xiangshan-source-audit-7.3.json)核对过固定来源的 234 个文件，其中 193 个 Scala 文件。

RTL 阶段有一项明确适配：**暂存副本中 14 处固定 stdout/stderr `$fwrite` 转为可观察日志**，原始 RTL、描述符和来源哈希保留。不是所有 RTL 文本都原样送进 Yosys，也没有删除不认识的行为来假装通过。原始 ClockGate 实现和 Difftest 头文件均收集进入工程；没有默认添加 `SYNTHESIS` 或 `DIFFTEST` 宏。

## 7. 学长接下来优先做什么，怎样算验收

1. **先拿到当前 table 任务的实际结果。** 如果失败，按日志定位 Python 导入、IR 写出、Lean 解码还是编译；记录峰值内存。当前主要卡点是整颗规模，不是再补几个小模块测试。
2. **让完整 table 模型通过 Lean 编译和全数据校验。** 必须有完整模型的 `C2L_TABLE_CHECK`，节点及字段数与 manifest 一致；只编译通用解释器或空包装不算完成。
3. **执行整颗模型。** 明确初态和复位，先跑一个全局采样步，再跑短序列，测每步耗时、峰值内存及稠密存储器成本。编译通过不代表有可用执行性能。
4. **补完整顶层的独立 RTL 对照。** 建立同一时钟、初态、复位和外部总线/内存响应环境；先做定向短轨迹，再进入指令运行场景，比较输出和选定观察状态。不能直接用全随机顶层输入触发断言后判断转换错误。
5. **扩大实际模块和配置覆盖。** 在整颗问题定位需要时补完整 BPU、缓存等模块的独立回归，之后再扩多核或其他配置。每个配置分别展开和验收。

本阶段“做出来”的验收标志是：**同一份完整 `XSTop` 的来源可追溯，Lean 全量生成、校验、编译和执行通过，并在明确环境约定下与独立原始 RTL 的顶层轨迹一致。** 全部阶段应有命令、退出码、产物哈希和可复跑报告。

若要求“所有合法输入序列都等价”，还需要单独的语义保持证明或分层证明工作；有限差分测试不能替代它。不要通过删断言、换简化 SRAM、丢掉初态约束或隐式全零来满足上述验收。
